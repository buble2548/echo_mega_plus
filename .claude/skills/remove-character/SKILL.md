# ลบตัวละครออกจากเกม ECHO

ไม่ใช่แค่ลบ `characters/<id>.js` — ตัวละครหนึ่งตัวแทรกตัวอยู่ทั่ว engine, ฝั่ง client,
ทะเบียนสถานะกลาง, CSS และเทสต์ ของโอเบรอนตัวเดียวมี **600 จุดใน 17 ไฟล์** ถ้าไล่ไม่ครบ
เกมจะพังตอนรันจริงแบบเงียบๆ (`CHAR_HOOKS.<id> is undefined`) ไม่ใช่ตอน build

## ไล่ให้ครบก่อนแตะอะไร

```bash
grep -rn "<id>\|<Id>\|<ID>" --include=*.js --include=*.jsx --include=*.css . \
  | grep -v node_modules | grep -v client/dist
```

ต้องค้นทั้งสามรูปแบบตัวพิมพ์ เพราะโค้ดใช้ปนกัน: `oberon` (id/ฮุค) · `Oberon` (ชื่อคอมโพเนนต์
`KotarouModal`) · `OBERON` (ค่าคงที่รูป `OBERON_NIGHT_IMG`) และ **อ่านผลให้ครบก่อนลงมือ** —
รายการนี้คือเช็คลิสต์ ไม่ใช่แค่ตัวเลข

⚠️ **ระวังชื่อชนกัน** — `ktBasicLocked`/`ktSecLocked`/`ktUltLocked` เป็นของ **โคโตเนะ**
ไม่ใช่ **โคทาโร่** ต้องอ่านคอมเมนต์ข้างๆ ก่อนลบทุกครั้ง

## ลำดับที่ปลอดภัย

ไล่จาก "ปลายน้ำ" เข้าหา "ต้นน้ำ" แล้วเช็ค syntax ทุกก้าว — ถ้าลบ `characters/<id>.js`
ตั้งแต่แรก ไฟล์อื่นจะพังหมดจนหาจุดที่เหลือไม่เจอ

1. `server.js` (จุดเยอะสุด) → `node --check server.js`
2. `client/src/screens/Game.jsx` → `npx eslint client/src/screens/Game.jsx`
3. `characters.js` · `characters/_transforms.js` · `characters/index.js`
4. ไฟล์เล็ก: `audio.js` · `arena.css` · `CharacterSelect.jsx` · `BattleScenes.jsx` · `permanentStatus.js`
5. ค่อยลบ `characters/<id>.js` และ `tests/characters/<id>.test.js`
6. เทสต์ที่เหลือซึ่งอ้างถึงเขา (`computeAttackBase.test.js`, `modalMounts.test.js`)
7. `npm test` 2-3 รอบ · `npx eslint` · `cd client && npm run build`

## จุดที่ต้องถอนใน server.js

ใช้เป็นเช็คลิสต์คู่กับผล grep — ทุกบรรทัดที่ `add-character` บอกให้ "เสียบ" คือบรรทัดที่ต้อง "ถอน"

| หมวด | สิ่งที่ต้องถอน |
|---|---|
| ค่าคงที่ | `<ID>_*_IMG` ทั้งชุด **และชื่อที่ไปโผล่ในก้อน `img` ที่ส่งให้ `buildTransforms`** |
| ตัวแปร module-level | ธงสนามของเขา (`oberonDevour`) + ทุกที่ที่ reset และที่อยู่ในสแนปช็อตย้อนเวลา |
| ฮุค | `resetCombat` · `onRoundStartTick` · `canUseSkill` · `applyInstantSkill` · `damageBonus` · `tryAttackDodge` · `displayImg` · `publicState` · `maybeQueueIntro` |
| ด่านกลางเกม | `hit()` · `lock()` · `useSkill()` · `buyShopItem()` · `useInventoryItem()` · `endTurn()` |
| ฟังก์ชันเฉพาะตัว | ฟังก์ชันระดับไฟล์ที่เขียนไว้ให้เขาคนเดียว (`beginKotarouRewindDraw`) + ที่ export ให้เทสต์ |
| ก้อน state | ฟิลด์ใน `buildStateFor` + ธงฉากหลัง/เพลงสนาม |

**สแนปช็อตย้อนเวลา** (`captureTurnSnapshot`/`restoreTurnSnapshot`) มีรายชื่อตัวแปรซ้ำกัน 4 ที่
ในไฟล์ — ใช้ `s.replace()` ทั้งไฟล์ ไม่ใช่ลบทีละจุด

## เส้นแบ่ง: อะไรลบ อะไรเก็บ

นี่คือจุดที่ตัดสินใจผิดแล้วเสียหายทั้งสองทาง — ลบเกินทำให้ตัวละครอื่นพัง ลบขาดทิ้งโค้ดตายไว้

**ลบ** — สิ่งที่ตายไปพร้อมเขา:
- สถานะที่ **มีแต่เขาแจกได้** (`veil`, `dawn`, `vortarmor`, `oberonSickle`) รวมถึงชื่อใน
  `BUFF_KEYS` / `SOFT_DEBUFF_STEP` / `NO_TICK_STATUS` / `client/src/data/permanentStatus.js`
  และป้ายใน `STATUS_INFO` ของ `Game.jsx`
- คัตซีนทุกคีย์ใน `_transforms.js` · เพลงใน `audio.js` · CSS ฉากสนามของเขา
- ตัวแปรที่ destructure แล้วไม่มีใครผลิตอีก (`oberonZero` — เดิมเป็นโค้ดตายอยู่แล้ว)

**เก็บ** — ของกลางที่บังเอิญเขาเป็นคนใช้:
- สถานะที่ประกาศเป็น **Universal** และมี API ของตัวเองใน `_universal_status.js`
  (`curse` มี `applyCurse`/`tickCurseOnSkill` เหมือน `poison`/`shock`/`mend`) — เป็นคำศัพท์ร่วม
  ที่ตัวละครหน้าหยิบไปใช้ได้ ไม่ใช่เอฟเฟกต์ส่วนตัว
- ระบบแกนที่เขาแค่ไป**เกาะ** ไม่ได้เป็นเจ้าของ: วงจรกลางวัน/กลางคืน (`isNightRound`) ยังมี
  ภาษีกลางคืน โบนัสตอนเช้า และตัวละครอื่นอีกหลายตัวอ่านอยู่
- `sleep` ที่อยู่ใน `BASIC_DEBUFF_CLEAR` และมีท่อตายร่วม (`maybeWakeKotone`)

**ห้ามลบเด็ดขาด**: `client/public/characters/<id>/` — อยู่ใน `.gitignore` ลบแล้ว git กู้ไม่ได้
ปล่อยไว้ไม่เสียอะไร บอกผู้ใช้ว่าปล่อยไว้แล้วให้เขาตัดสินใจเอง (บน R2 ก็เช่นกัน)

## กับดักตอนลบ

**1. คอมเมนต์ไทยยาวๆ ลอกมาเทียบไม่เคยตรง** — เครื่องหมาย `—` vs `-`, ช่องว่างซ้อน, คำที่จำผิด
ไปหนึ่งคำ ทำให้ `assert s.count(a) == 1` ล้มเรื่อยๆ **อ้างจากบรรทัดโค้ดอย่างเดียว** แล้วค่อยไล่ถอย
ขึ้นไปกินคอมเมนต์เหนือมัน:

```python
i = next(k for k, ln in enumerate(lines) if 'CHAR_HOOKS.x.foo(' in ln)
start = i
while lines[start - 1].lstrip().startswith("//"):
    start -= 1
del lines[start:i + 1]
```

**2. บล็อก JSX ต้องปิดด้วยย่อหน้าเดียวกับบรรทัดเปิด** — `{xSel && (` ... `)}` ซ้อนกันหลายชั้น
ถ้าจับ `)}` ตัวแรกที่เจอจะตัดผิดที่แล้วเหลือ `</div>` ลอย เทียบ indent ของบรรทัดเปิดเสมอ:

```python
indent = len(lines[i]) - len(lines[i].lstrip())
j = next(k for k in range(i + 1, len(lines))
         if lines[k].strip() == ")}" and (len(lines[k]) - len(lines[k].lstrip())) == indent)
```

**3. กระดานมีสองชุด** (มือถือ + จอคอม) — ป้าย/โมดัล/แบนเนอร์ของตัวละครมักมีสองที่เสมอ
ลบที่เดียวแล้ว grep จะยังเหลือ

**4. บล็อกที่มีหลายบรรทัดต้องตัดให้ครบทั้งก้อน** — ตัดแค่บรรทัดแรกของ `if (k) { ... }` เหลือ
ตัวข้างในลอยอยู่นอกฟังก์ชัน `eslint` จะฟ้อง `'return' outside of function` ซึ่ง**ชี้ผิดที่**
ให้ดูบรรทัดที่มันฟ้องแล้วไล่ขึ้นไปหาก้อนที่เพิ่งลบ

**5. คอมเมนต์ท้ายบรรทัด `require` มีของตัวละครอื่นติดมาด้วย** — ใน `_transforms.js` คอมเมนต์
ของสามตัวละครถูกต่อกันอยู่บรรทัดเดียว ลบทั้งบรรทัดจะพาคำอธิบายของคนอื่นหายไปด้วย

**6. สำรองไฟล์ก่อนรันสคริปต์ลบ** — `cp server.js /tmp/server.bak.js` ทุกครั้ง สคริปต์ที่ assert
กลางทางจะทิ้งไฟล์ไว้ครึ่งๆ กลางๆ ถ้าเขียนแบบ write ทีละจุด (เขียนแบบสะสมใน memory แล้ว
write ครั้งเดียวตอนจบจะปลอดภัยกว่า)

**7. เทสต์ที่ตายตามต้องลบด้วย** — ไม่ใช่แค่ `tests/characters/<id>.test.js` แต่รวม assert
ที่ฝังชื่อเขาไว้ในเทสต์รวม (`computeAttackBase.test.js` มีเทสต์ของ `veilAtk`/`oberonZero`,
`modalMounts.test.js` มีชื่อโมดัลของเขา)

## บทเรียนจากการตรวจบัค (ใช้ได้ทั้งตอนลบและตอนเพิ่ม)

บัคที่เจอซ้ำๆ ในโค้ดเบสนี้มาจากรากเดียวกัน: **แกนร่วมที่ตัวละครหลายตัวใช้**

**ฮุคร่วมถูกเรียกซ้ำ** — `server.js` เรียก `CHAR_HOOKS.a.onRoundStartTick(p)` และ
`CHAR_HOOKS.b.onRoundStartTick(p)` กับผู้เล่น**ทุกคน** ถ้าทั้งสองไฟล์ส่งต่อให้แกนร่วมที่
ด่านเป็น "เป็นตระกูลนี้ไหม" ผลจะถูกคิดสองรอบ (Clock Up เคยกินแต้ม 4/เทิร์นแทน 2)
→ **ทุกฮุคต้องมีด่าน id ตัวเองก่อนส่งต่อให้แกนร่วมเสมอ** และเทสต์ควรเรียกฮุคของ**ทุกตัวในตระกูล**
เหมือนที่ server ทำจริง ไม่ใช่เรียกแค่ตัวที่กำลังเทสต์

**สถานะของสนามต้องตัดสินจากสนาม** — `syncClockUpPhaseTime(p)` เคยดูจากไรเดอร์คนที่เพิ่งกดปุ่ม
พอคนหนึ่งปิด เวลาเดินต่อทั้งที่อีกคนยังแช่อยู่ → อะไรที่เป็นกติกาสนาม ให้ถามสนาม
(`freezeHosts(engine).length`) ไม่ใช่ถามผู้เล่นคนเดียว

**`triggerCutscene` เล่นคลิปเต็มครั้งเดียวต่อเกม** — เหตุการณ์ที่ควรเห็นทุกครั้ง (สลับร่าง
ตามเวลา, เปิดท่าที่กดซ้ำได้) ต้องใช้ `queueCutscene` ไม่งั้นครั้งที่สองเป็นการ์ดเล็กๆ
แล้วผู้เล่นจะรายงานว่า "ไม่เปลี่ยนร่าง"

**ทางที่ `return` ก่อนถึงปลายทาง** — ด่านหลบใน `doAttack` return ตั้งแต่ต้น ไม่ผ่าน
`postAttackFollowup` อะไรที่ต้องเกิด "ทุกกรณี" ให้แขวนไว้ที่ `endTurn()` ซึ่งเป็นปลายทางร่วม
ของทุกทาง (โดน/ถูกหลบ/ถูกสะท้อน/ถูกลบล้าง)

**`clip-path` ตัดลูกหลานทุกตัว** — ไม่สนใจ `z-index` หรือ `overflow` ป้ายที่วางไว้ `-top-2`
บนการ์ดที่มี clip-path จะหายทั้งใบ เหลือแต่เงาที่เล็ดลอดออกมา ป้ายที่ลอยพ้นขอบต้องอยู่**นอก**
element ที่ถูก clip

**โค้ดตายที่อ้างฟังก์ชันไม่มีจริง** — `engine.fieldFreezeByOther` เรียก `clockUpHost` (เอกพจน์)
ที่ไม่มีอยู่ ไม่ระเบิดเพราะไม่มีใครเรียก แต่เป็นกับระเบิดรอคนต่อสาย → ตอน grep เจอชื่อฮุค
ให้เช็คด้วยว่า**มีจริงไหม** ไม่ใช่แค่ว่าถูกเรียกไหม

## เขียนคำอธิบายให้ผู้ใช้

ผู้ใช้เป็นคนไทย ใช้ภาษาไทย และบอกให้ครบสามอย่างเสมอ: **ลบอะไรไป** · **อะไรเก็บไว้และทำไม** ·
**อะไรที่ไม่ได้แตะ** (โดยเฉพาะไฟล์สื่อที่ gitignore ไว้) — การเก็บของกลางไว้ไม่ใช่ความขี้เกียจ
แต่ต้องบอกเหตุผล ไม่งั้นดูเหมือนลบไม่ครบ
